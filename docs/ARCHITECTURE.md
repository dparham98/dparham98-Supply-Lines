# Scene and asset setup

Terrain rendering is no longer generated by terrain_grid.gd. The Ground node's mesh, shader material and collision are authored in terrain.tscn; the terrain grid script only loads raw map cells, occupancy and A* navigation. terrain_assets.gd exposes editor asset slots and a bake button; terrain_baker.gd extracts static mesh parts from prop scenes and writes terrain_landmarks.tscn. Native saved MultiMesh resources make scenery visible before _ready and avoid generating thousands of individual tree nodes in the editor. Lighting and UI are separate scenes.

Base ground rules: grass/desert open, other four categories blocked; Scout/Tank forest mobility and separate Drone air occupancy are described in TERRAIN_ABILITIES.md. Tank clearing is match-local state; raw 500x500 categories are independent from visual textures. Keep assets/maps/terrain_data.png lossless/no mipmaps/no automatic 3D compression. source_map.png contains the unchanged original map pixels. Changing the map image alone does not regenerate categories or surface art; regenerate both together with a validated map-data workflow.

Actors find the terrain by the terrain_grid group rather than a sibling path. Headquarters uses the headquarters group for camera focus. Unit visuals are independent PackedScene slots. Root positions are ground pivots; placeholder meshes are positioned inside their model scenes. With Use Editor Position enabled, runtime derives the initial cell from authored placement and validates terrain. Camera/units/buildings containers must remain untransformed until movement is generalized to transformed parents. Existing health/combat/destination reservation logic remains; no new physics/crowd solver, harvesting, terrain height or production model was added.

SelectionManager is a single autoload. The earlier manager called a missing set_selected method and only selected the first unit in a drag; the refactor adds the method/ring and handles all player units in one manager. Enemy input is passive. Attack action remains A; camera keyboard movement uses arrows. Selection feedback and click/drag behavior are regression-checked through the manager.

Validation: terrain_test.gd checks all terrain categories, placement release rules, coordinate mapping, HQ footprint and land spawns, diagonal-safe paths and a unit following waypoints. scene_setup_test.gd checks native visuals exist before ready, default batch counts, model-slot replacement, a single-mesh terrain prop replacement, and saving/reloading the terrain rebuild. It renders the world with all gameplay/tool scripts removed as a static visibility check; this is not a screenshot of the desktop editor UI. Tests do not certify animation, imported rig compatibility, performance at large army sizes or undo/redo for editor tool operations. Terrain rebuild writes its generated scene; old generated batches have no dedicated undo stack.

build_initial_scenes.gd is a one-time bootstrap source, not a normal editor workflow; rerunning it recreates default scenes. Normal changes should use the scenes and Inspector slots described in README.md. GitHub is the authoritative version-controlled source. Develop in cloud clones on feature branches and submit pull requests for review. Keep the local Windows checkout for visual and gameplay testing; do not update historical OneDrive archives. Never force-push main or merge unverified gameplay changes.

Camera behavior lives on the CameraRig root, with YawPivot/PitchPivot/Camera children. Inspector settings, flat-ground targeting, input actions and validation are described in CAMERA_RIG.md.

First Contact adds a separate resource_skirmish.tscn playable entry and scripts/gameplay state machines. The earlier review world and actor scripts are preserved. See FIRST_CONTACT.md for ownership, grid claims, orders, production, limitations and tests, and RECOVERED_DESIGN.md for confirmed versus provisional rules.
